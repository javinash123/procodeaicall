Issues Found in User Login & Dashboard
🔴 Critical (Broken Functionality)

1. Feature gate name mismatch — ALL gated features broken for ALL users Plan features stored in the DB use human-readable names ("Basic CRM", "Analytics", "Bulk WhatsApp", "Bulk SMS") but requireFeature() on the server and FeatureGate on the frontend check for system keys ("crm", "analytics", "whatsapp", "bulk_sms", "campaigns", "calendar", "call_history"). Since "Basic CRM" !== "crm", every feature-gated section returns 403 from the API and shows "Upgrade Required" in the UI — for every user on every plan, including Enterprise.

2. Change Password is broken — 404 The Security tab in Profile calls POST /api/user/change-password, but this route does not exist. The actual route on the server is POST /api/users/:id/password. Every password change attempt silently fails.

3. Duplicate "Basic" plan in DB Two active "Basic" plans exist: one with correct features, one with an empty features: [] array. New registrations on the free plan may end up assigned to the empty-features version, locking them out of everything even if the name mismatch were fixed.
🟠 High (Partially Broken)

4. Razorpay Key ID missing — payment will fail VITE_RAZORPAY_KEY_ID is not set as an environment secret or .env variable. The payment page falls back to the literal string "rzp_test_placeholder", which means the Razorpay checkout modal will open but all payments will be rejected.

5. Post-registration paid-plan login message not shown After successful payment, users redirected to /login?message=Account activated successfully... never see that message — the login page reads queryParams but does not render the message param as a toast or banner anywhere.

6. "Forgot Password" link is dead The login form has a "Forgot password?" anchor (href="#") that does nothing. There is no reset password route, no email flow, no UI — it's a broken dead link.
🟡 Medium (Incorrect Behavior)

7. Credit Usage chart uses random fake data The credit usage chart in the billing section is generated with Math.random() on every render instead of real usage data pulled from the database.

8. "Call Support" misspelled in Enterprise plan The Enterprise plan has the feature named "Call Suport" (missing 'p'). Even after fixing the name mismatch, this would prevent it from matching any valid feature key.

9. Upgrade button in billing tab may resolve the wrong plan The "Renew Now" button correctly navigates to /payment?plan=<id>&renew=true, but if the user's plan name matches the duplicate empty-features "Basic" plan, currentPlan will be undefined and the button is disabled (the currentPlan && guard silently hides it).
🔵 Minor / UX

10. Dashboard header search bar is non-functional The search input in the top header of the dashboard is a visual-only element — it has a placeholder but no onChange, no search logic, and no results display.

11. /auth route returns 404 Navigating to /auth shows a 404 page. The correct paths are /login and /register. Any external link or old bookmark pointing to /auth breaks.

12. Dashboard file exceeds 500KB — Babel deoptimised The build log shows Babel deoptimised dashboard.tsx (>500KB). This slows cold-start compile time and signals the file needs splitting, though it doesn't break functionality today.
